# 中国党政机关政策文件索引采集

产出一张可逐条复核的索引表，每条都能点回官方原文。抓不到就留空，绝不编造 URL 或日期。

## 核心原则：不预设任何站点的结构

**这个 skill 不附带脚本，也不内置选择器。** 政府网站模板各异、改版频繁、JS 渲染比例逐年上升，任何写死的 XPath/CSS 都是定时炸弹——上个季度能跑，下个季度静默返回空。

正确做法：每次现场量一下页面，按下面的判据决定用什么手段，临场写一次性代码，用完即弃。**一次性代码不进 skill**；只有稳定的事实（接口参数、源状态、坑）才沉淀在这里。

## 源入口规律

政府站的模板换得比想象中勤——机构改革后栏目整并、CMS 升级、域名迁移，任何「某站能抓 / 不能抓」的结论几个月就失效。**记规律和指纹，现场量。**

### 一、三类站点的入口

| 层级 | 入口 | 说明 |
|---|---|---|
| 中央 | 国务院政策文件库（入口 A） | 有统一检索接口，**别去抓它的页面** |
| 部委 | `www.<机构缩写>.gov.cn` → 政务公开 → 政策文件 | 缩写无统一规则，用下面第四节的办法反查 |
| 省 / 市 | `www.<省简称>.gov.cn` → 政务公开 → 政策文件库 | 部分省市把"政策文件库"做成独立子站或独立路径 |

国家级文件、部委规章、地方文件是**三套不同的库**，互不覆盖。找全一个主题往往要三处都过一遍。

### 二、栏目路径有常见词根，但没有统一规范

政策文件栏目的路径词根确实集中，3–4 层就到底了。下面这些覆盖相当一部分站点，值得先试：

```
政务公开层：/zwgk/  /xxgk/  /zfxxgk/  /gongkai/  /gkml/
文件层：    /zcwj/  /zcfg/  /zhengce/  /zhengcefabu/  /zcfb/  /fgzc/  /wjk/
细分类层：  /qbwj/（全部文件）  /gfxwj/（规范性文件）  /bmgz/（部门规章）  /fdzdgknr/（法定主动公开内容）
```

常见组合：`/xxgk/zcfb/`、`/zwgk/zcwj/`、`/zfxxgk/fdzdgknr/zcwj/`、`/zwgk/wjk/qbwj/`。

**但这张表只是候选，不是规范。** 同一部门改版后路径整体换掉、栏目名从「政策文件」改成「文件发布」「政务公开目录」、或者干脆搬到独立子站/统一政务服务平台，都很常见。拼不出来是常态，不是路径没背熟。

**猜了两三轮拿不到，就别再盲拼，改按名称检索。** 让搜索引擎告诉你这个栏目到底叫什么、在哪：

```
"<部门全称>" 政策文件
"<部门全称>" 规范性文件 site:gov.cn
"<省/市名>" 政策文件库
"<部门全称>" 规章 通知公告
```

从结果里挑**列表页**（不是某篇具体文章）落地，再回第 0 步量字节数。按名称检索比穷举路径快，而且能区分两种完全不同的失败：**路径猜错了**（换个词根就行）和**这个站根本没有独立政策栏目**（再把所有词根试一遍也白费）。

确实有一类站没有独立政策栏目：文件散在「通知公告」「新闻动态」里，或只发在公众号。这种情况不要硬造目录，直接抓通知公告流，或者退回入口 A 按发文机关筛。

### 三、URL 指纹与 CMS 类型

| URL 形态 | 常见来源 | 对抓取的意味 |
|---|---|---|
| `col/col<数字>/index.html` | 栏目 ID 制的省级政务网 | 栏目号无规律，**别拼 URL**，从页面导航进 |
| `t<YYYYMMDD>_<数字>.htm` | TRS 系（部委老站常见） | 文件名里的日期是入库号，≠ 发布日期 |
| `content_<数字>.htm` 且目录带 `/YYYYMM/` | gov.cn 自家 | 目录年月可辅助定位 |
| `post_<数字>.html` | 帖子式 ID 的省级站 | 完全不含日期，日期只能从列表取 |

**文章 URL 普遍带年月**（`/202611/`、`/2026-11/05/`），可以用来推测所属月份，但**不能当发布日期**（见前文那个坑）。

**翻页不要猜 URL 模式。** 找页面上文本为「下一页 / 下页 / > / >>」的链接，或 `rel="next"`；找不到就说明是 JS 分页，走第 3 步。

### 四、查一个陌生部门的入口

1. **反查域名**：在政策库里搜一条该部门的文件，看返回 `url` 的域名——落在 `xxx.gov.cn` 的就是它官网（落在 `www.gov.cn` 的是转载稿，跳过）。
2. **进政策栏目**：首页「政务公开 / 信息公开」→「政策文件 / 规范性文件 / 规章」。栏目名对不上就按第二节的词根试两轮，**仍不行就搜「<部门全称> 政策文件」定位**，别继续拼 URL。
3. **量一下**：按第 0 步的字节数判据决定静态解析还是上浏览器。
4. **还不行就看 XHR**：第 3 步第一层，多数站的前端都在调自己的接口。

**要找的是"这个部门下面有哪些局"而不是"有哪些文件"**，去门户的机构页，不在政策栏目里。机构页的词根也相对固定：

```
/zwgk/zfjg/                                （政府机构，省、地级市最常见）
/zwgk/szfjg/  /zwgk/szfjj/                 （省政府机构，带层级前缀的写法）
/gongkai/zfxxgk/fdzdgknr/jgzn/             （机构职能，挂在法定主动公开内容下）
/col/col<数字>/index.html                  （栏目 ID 制，只能从导航进）
```

注意**这类页面的机构名常是 JS 加载的**：抓下来只有「省政府组成部门」「省政府直属机构」这些分类标题，一个部门名都没有。判断方法很简单——搜一个你确定存在的部门名（如"教育厅"），HTML 里搜不到就是 JS 渲染。碰上这种别急着上浏览器，先看它 `ColumnKeywords` 之类的 meta 里有没有塞一串部门名。

### 五、两个常见误区

- **不要拿"某个站上次能抓"当依据。** 同一部门换 CMS 后，原来的 CSS 选择器和翻页规则会同时失效，而且失败方式是静默的——返回 200 和空列表，不报错。
- **不要为了一个栏目页去对抗前端。** 该部门在政策库里通常有对应文件；栏目的价值是补政策库没收录的部分，不是替代它。

## 第 0 步：先量字节数，再选手段

```bash
curl -s -o /tmp/p.html -w "HTTP=%{http_code} bytes=%{size_download}\n" \
  -A "Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 Chrome/131.0 Safari/537.36" \
  "<栏目URL>"
```

判据（2026-11 实测校准）：

| 结果 | 含义 | 下一步 |
|---|---|---|
| `200` + `bytes > 10000` | 静态渲染 | 直接解析，走入口 B |
| `200` + `bytes < 3000` | JS 壳 / 反爬挑战页 | 别调选择器，走第 3 步 |
| `200` + `bytes` 几十字节 | 跳转脚本 | 读内容找真实地址，重新量 |
| `403` / `412` | 有 WAF | 换接口或上浏览器 |
| `200` 但解析出 0 条 | 结构变了或判断粒度错 | 回入口 B 的粒度规则检查 |

**不要看到 200 就开始写选择器。** 2–3 KB 这个量级基本可以断定是壳：源码里全是 `<script>`，一条文章都没有，无论它是哪个部门的站。gov.cn 自家也有返回 200、但正文完全由 JS 渲染的栏目页。

几十字节那种通常是 `window.location.href='./xxx/'`——栏目已迁移或合并，读这个脚本拿到新路径重新抓，别在原地址上纠缠。

## 入口 A：国务院政策文件库 JSON 接口

不走 HTML，直接拿 JSON，不受页面改版影响。

```bash
curl -s -G "https://sousuo.www.gov.cn/search-gov/data" \
  --data-urlencode "t=zhengcelibrary_gw" \
  --data-urlencode "q=人工智能" \
  --data-urlencode "searchfield=title" \
  --data-urlencode "p=1" \
  --data-urlencode "n=100" \
  --data-urlencode "sort=pubtime" \
  --data-urlencode "sortType=1" \
  -H "User-Agent: Mozilla/5.0 (X11; Linux x86_64) AppleWebKit/537.36 Chrome/131.0 Safari/537.36" \
  -H "Referer: https://www.gov.cn/"
```

结果在 `searchVO.listVO[]`：

| 字段 | 含义 | 备注 |
|---|---|---|
| `title` | 标题 | 含 `<em>` 高亮，必须清洗 |
| `pubtimeStr` | 发布日期 `2026.10.23` | 点号分隔；偶为 `null` |
| `pubtime` | 毫秒时间戳 | `pubtimeStr` 空时兜底 |
| `url` | 原文直链 | `www.gov.cn/zhengce/zhengceku/...` |
| `puborg` | 发文机关 | 「国务院办公厅」「财政部」 |
| `pcode` | 文号 | `国办发〔2026〕29号` |
| `index` | 索引号 | `000014349/2026-00076` |
| `childtype` | 主题分类 | `劳动、人事、监察\劳动就业` |
| `summary` | 正文摘要 | 含 `<em>`，约 100 字 |

### 接口参数的四个约束

1. **`t` 必须是 `zhengcelibrary_gw`**。写成 `zhengcelibrary` 会返回 `totalCount=0`，但 `facetMap` 里仍有部门/年份统计，容易被误判成"接口正常只是没结果"，转而去别处绕圈子。
2. **`timetype` / `mintime` / `maxtime` 服务端不生效**。传了时间范围，返回的 743 条里照样混着 2017 年的文件。必须拉回来在本地按 `pubtime` 裁，这三个参数不可依赖。
3. **`n` 上限 100**。传 `n=200` 返回非 JSON（服务端直接拒），容易被误当成限流。
4. **没有可用的部门过滤参数**。`bmfl=`、`fwdw=` 被静默忽略（total 不变），`puborg=` 会让 `searchVO` 变成 `null`。要按部门筛，只能在客户端过滤抓回来的 `puborg` 列，或 `searchfield=title` + `q=<部门名>`。

### 两个用法要点

- **`q=''` + `sort=pubtime` = 最新政策全量流**（total ≈ 6229）。这是"最近发了什么"最干净的入口，比翻列表页可靠。
- **`searchfield=title` 和 `quanwen` 差一个数量级**：q=人工智能 时，title 命中 3 条，quanwen 命中 743 条。要列政策文件就用 `title`；`quanwen` 召回的大多是正文里顺带提了一句的文件。

> 对应中央那 17 个国家局：省级一般把「国家 XX 局」改成「省 XX 局」，归口省发改委（能源局）、省卫健委（疾控局、药监局）、省司法厅（监狱局）等管理。

**直属事业单位（7）**：科学院、社会科学院、农业科学院、医学科学院、地质局、供销合作总社、公共资源交易中心

> **省社科院、省农科院、省医科院是省级特有的**，中央对应的是中国科学院、中国社科院。找这类文件别在国务院库里搜。

⚠️ **这不是全国通用清单。** 省级机构按各省《机构改革方案》设置，组成部门数量、归口关系、甚至有没有「数据局」都因省而异。**换一个省，必须重新拉该省的机构页**，拿河南的清单去套广东会错。

### 市级：平铺一张表，或自定义类别

**地级市（佛山样本）**：市政府门户「政府机构」页是 **30 个单位平铺，完全不分类**——1 个「市政府办公室」+ 29 个局。没有"组成部门 / 直属机构"这种区分，看页面上就是一张名单。

**直辖市（北京样本）**：机构职能页有分类，但**类别名和中央、省都不一样**：

| 北京的实际分类 | 说明 |
|---|---|
| 市政府办公厅 | 同名 |
| 市政府组成部门 | 同名（25 个） |
| 市政府直属特设机构 | 同名（只有市国资委） |
| 市政府直属机构 | 同名（13 个） |
| **其他机构** | 中央/省没有这一层，把事业单位、部门管理机构、开发区管委会、执法总队全塞进来（15 个：天安门地区管委会、重点站区管委会、经开区、城市副中心管委会、城管执法局、监狱局、粮食和储备局、中医药局、药监局、疾控局、重大项目办、文化市场执法总队、投资促进服务中心、住房公积金管理中心、地震局） |

→ **这就是"别按类别筛、只能按名字筛"的实证**：同一个「药品监督管理局」，河南归"部门管理机构"，北京塞进"其他机构"，佛山压根不分类。

### 名称与层级的对应

| 层级 | 教育 | 卫生健康 | 发展改革 | 市场监管 |
|---|---|---|---|---|
| 中央 | 教育部 | 国家卫生健康委员会 | 国家发展和改革委员会 | 国家市场监督管理总局 |
| 省 | 省教育厅 | 省卫生健康委员会 | 省发展和改革委员会 | 省市场监督管理局 |
| 直辖市 | 市教育委员会 | 市卫生健康委员会 | 市发展和改革委员会 | 市市场监督管理局 |
| 地级市 | 市教育局 | 市卫生健康局 | 市发展和改革局 | 市市场监督管理局 |

三条判据：

1. **「厅」只在省级出现**（中央只有一个国务院办公厅）。文件署名带「XX 厅」，就是省级文件，别去国务院政策库找。
2. **「委」在中央、省级、直辖市是常态，地级市少见**（地级市多是「局」）。北京叫「市教委」，佛山叫「市教育局」。
3. **地级市门户爱用简称**：佛山写「市发改局」「市卫健局」「市人社局」「市文广旅体局」，而**正式发文署全称**「佛山市卫生健康局」。按名字检索时**简称和全称都要试**，用包含匹配。

### 命名与检索上的四个陷阱

1. **`puborg` 里不带"中华人民共和国"前缀**。是「财政部」不是「中华人民共和国财政部」，是「文化和旅游部」不是全称。筛的时候用**包含匹配**，别用等值。
2. **挂牌 / 保留牌子的机构会作为发文主体出现，但它们不是独立机构**。原文件明确写了这些：教育部对外保留**国家语言文字工作委员会**牌子；工信部对外保留**国家航天局**、**国家原子能机构**牌子；人社部加挂**国家外国专家局**；自然资源部对外保留**国家海洋局**；生态环境部对外保留**国家核安全局**；农业农村部加挂**国家乡村振兴局**；市场监管总局对外保留**国家反垄断局**、**国家认证认可监督管理委员会**、**国家标准化管理委员会**；移民局加挂**出入境管理局**；林草局加挂**国家公园管理局**。
   → 找这类文件时，**主机构名和牌子名都要试**。比如"标准化"相关文件，`puborg` 可能就是「国家标准化管理委员会」。
3. **「厅」只出现在省级**（中央只有国务院办公厅，地级市一律用「局」）。看到「XX 厅」发的文件，说明那是省级文件，不该在国务院政策库里找。市级文件的署名是「XX 市教育局」「XX 市卫生健康局」，不会叫「市教育厅」。
4. **同一个局可能两份文件署名不同**（规范全称 vs 简称 vs 牌子名）。去重时按 `url`，不要按机关名。地方门户列表里的简称（「市卫健局」）和正式署名的全称（「佛山市卫生健康局」）尤其容易对不上。

### 检索某个部门的顺序

```
1. searchfield=title + q="<部门简称>"        → 标题里点了部门名的（如"财政部关于…"）
2. searchfield=quanwen + q="<部门简称>"      → 正文提到的，召回高但噪声大
3. 直接抓该部门官网栏目页（入口 B）           → 部委自己的规范性文件很多不进国务院文件库
4. 抓回来后按 puborg 做包含匹配过滤
```

**第 3 条不能省。** 国务院政策文件库收录的是"报备"的文件，部委大量日常规范性文件只在自己官网发布，政策库里根本没有。

## 入口 B：部委 / 省市栏目页（现场解析）

这类页面没有统一接口，必须现场判断结构。**用判据，不要套模板。**

入口 URL 怎么找，见前面「源入口规律」第四节；下面只讲拿到 URL 之后怎么解析。

### 解析的粒度规则

政府列表页典型结构是 `<ul><li><a>标题</a><span>2026-11-05</span></li></ul>`。

正确做法：**以单个条目为单位取文本**——从链接往上找，停在"只包含这一个文章链接"的最近祖先，然后在这个范围里找日期。

错误的做法：往上追到 `<ul>` 或整块 `<div>` 再取文本。那样会把整列 20 条的日期混在一起，结果是**条条错位**，而且不会报错——曾遇到一条实际 11-05 发布的文件，被打上了隔壁条目的 11-11。

判据：如果取文本的那个节点里，长度 ≥6 的链接数量 > 1，说明粒度已经过粗，退回上一层。

### 抽取规则

1. 找**重复出现的容器**：同一父节点下 ≥10 个结构相同的子节点，基本就是列表项。
2. 每个条目里应同时有「一个 6–120 字的链接」+「一个日期」。缺日期的直接丢——导航、页脚、"更多>>"全是无日期链接，这条过滤能干掉 90% 噪声。
3. 日期正则覆盖 `2026-11-05`、`2026.11.05`、`2026年11月5日`、`2026/11/05` 四种写法。
4. 翻页：优先找文本为「下一页 / 下页 / > / >>」的链接或 `rel="next"`。翻到该页最老日期早于目标起始日就停。

### URL 里的日期不是发布日期

**URL 里的日期不是发布日期。** 见过文件名是 `t20261105_xxx.htm`、实际发布日期却是 **2026-11-11** 的情况——`20261105` 只是入库/内容号（开正文页核实过）。所以：以列表页显示的日期或正文页「发布日期」为准，**不要用 URL 里的数字反推**。这条对 TRS 系（`t2026MMDD_xxxxxxx.htm`）尤其要当心。

## 第 3 步：JS 渲染 / 反爬站点

静态抓不到时，**借助能控制浏览器的工具**，不要硬解混淆脚本、也不要靠猜接口路径。

### 工具优先级

1. **DevTools / Playwright 类 MCP**（环境里已挂载的话优先用）—— 能看 Network、能执行 JS、能取渲染后的 DOM，且请求由真实浏览器发出，TLS 指纹和 UA 都是正常的。
2. **浏览器自动化 CLI 或库**（`agent-browser`、`playwright-cli`、`playwright` / `puppeteer` 等）—— 没有 MCP 时用这些，能力等价。
3. **自己起 Playwright 脚本** —— 最可控，但要单独装浏览器内核。用 `uv run --with playwright` 之类的隔离方式，别污染项目依赖。

**禁止用 computer use / 系统级鼠标键盘接管整台电脑。** 抓政策文件不需要也不该接管用户桌面：会抢焦点、打断用户正在做的事，而且靠截图识别坐标比选择器脆弱得多。需要"像人一样点"时，用浏览器工具内的定位能力（CSS/XPath 选择器、无障碍树、元素 ref），不是系统鼠标坐标。

### 用浏览器工具的两个层次

**第一层：侦察 XHR，拿到接口就走人。**
页面打开后先看它自己发了哪些请求——政府站的前端也是在调自家的 `/search`、`/list.json`、`/api/query`。一旦找到，立刻切回普通 HTTP 客户端直接打那个接口，**不要继续用浏览器解析 DOM**。这一步能让大部分"JS 渲染"问题直接消失。

- DevTools MCP：看 Network 的请求列表，能复放就直接复放。
- Playwright：注册响应监听，过滤 `Content-Type: application/json`：

```python
page.on("response", lambda r: print(r.url) if "json" in (r.headers.get("content-type") or "") else None)
```

**第二层：等渲染完成再取 DOM。** 找不到接口才走这条。

- 等的是**目标元素出现**，不是固定 sleep：`wait_for_selector("<列表项选择器>")`，或等 `networkidle`。
- 取回的 HTML 仍然按入口 B 的粒度规则解析——不要因为"是浏览器抓的"就放松判断。

### 另外两条路子

- **数据开放 / RSS**。部分部委提供 `rss.xml` 或"数据下载"栏目，比抓页面稳。
- **换入口**。gov.cn 那类站有正规检索接口（见入口 A），没必要为了一个栏目页去对抗它的前端。

### 反爬与 403 的边界

真实浏览器能过大部分 WAF（同一目录页裸 requests 返 403、浏览器里正常，很常见）。但：

- **不要为了过验证码去模拟人机交互或接打码平台。** 换该站的检索接口、RSS 或政策库正规入口，更省事也更符合这些站点的使用预期。
- **不要索取或使用账号密码。** 需要的栏目若必须登录，用用户已登录的浏览器配置目录（Playwright `launch_persistent_context(user_data_dir=...)`），并事先说明会用到他的登录态。

## 交付前自检

- [ ] 抽 2–3 条链接实际打开，确认标题与表内一致、没跳到首页或 404
- [ ] 日期范围覆盖住用户要的时段（列表页模式最容易因翻页不足而截断）
- [ ] 有没有混进「解读 / 图解 / 答记者问 / 媒体评论」——这些常在相邻栏目，不算政策文件
- [ ] 日期和标题是否条条对应——解析粒度选粗了会**静默错位**，不报错
- [ ] 有没有把同一条目重复计入（翻页时首尾页重叠是常见的）

## 不做的事

- 不抓正文、不下载附件——需要正文或附件时再单独处理
- 不跨站聚合后"推断"发文机关或文号
- 不把第三方转载站（北大法宝、地方政府转载版）当一手源；非要用就明确标注为非官方
